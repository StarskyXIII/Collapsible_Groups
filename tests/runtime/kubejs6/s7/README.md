# S7 native NBT runtime fixtures

These client scripts target Minecraft 1.20.1 with EMI and KubeJS 6. The controlled instances `CG Audit S7 Fabric 20260909` and `CG Audit S7 Forge 20260909` completed the phase-01, phase-02, and phase-01 recovery sequence on 2026-09-09. See the [version notes](../../../../docs/minecraft-1.20.1.md) for the tested dependencies and artifact hashes.

In a disposable test instance, copy `01-nbt-v1.js` to `kubejs/client_scripts/cg_s7_nbt_runtime.js`, launch the client, enter a world, and open an inventory container screen. Keep the complete client log. The script first exercises `source.nbt(...)` and `source.nbtPath(...)` through the real Rhino callback, then waits for publication and checks the published groups against the same fixed stacks.

The first fixture asserts complete root-tag equality independent of item ID and count; strict byte-versus-int behavior; native bare-token string parsing; nested compound, list, typed-array, indexed, and JSON-quoted-key paths; ordered typed-list and byte/int/long-array equality; `any`, `all`, and bounded nested logic; `not(path == value)` matching missing and present-unequal values; and `UNAVAILABLE` remaining unavailable beneath `not`. Native `TagParser` cannot parse an empty compound key, so the unusual/empty-key path sample is built with native `CompoundTag` methods while the remaining complex samples use valid SNBT through `Item.of`.

While the client remains open, replace the active script with `02-invalid-builders.js`, press `F3+T`, and open the inventory again. This fixture checks the exact public exception messages for a scalar root, trailing root input, empty path, wildcard path, trailing expected-value input, a heterogeneous list, and a wrongly typed native-array element. Rhino exposes the caught Java exception through `error.javaException`, so the fixture reads its native `getMessage()` value before its existing fallbacks and still compares the complete public message byte-for-byte. Each rejected call is caught deliberately, and a valid peer is then registered. It also checks that omission removes the first fixture's source.

Before copying a fixture, verify it against `manifest.sha256`. For each loader, compare each three-line inventory-gated sequence byte-for-byte and in order with `expected.json`: ARMED, callback PASS, then publication PASS. Verify any callback PASS emitted during resource reload separately with the adjacent `Reloading ResourceManager` line; it is additional reload evidence rather than part of the gated sequence. A missing line, extra `[CG-S7-NBT-AUDIT] assertion failed` line, script error, timeout, or differing value is a failure. Re-copy `01-nbt-v1.js` and reload once more if a final recovered state is required; its phase 01 assertions must pass again.

A resource reload can produce the semantics or builder-rejection PASS before the inventory trigger. The inventory-triggered sequence then emits ARMED, repeats that callback PASS, and emits publication PASS. Check both intervals without treating a callback PASS alone as proof of publication. `expected.json` contains the verified inventory-gated messages; the observed results below record the completed runs.

These fixtures do not claim editor UI, saved-file round-trip, or invalid-recollection atomicity. Those require the separate UI/runtime acceptance steps and cannot be inferred from caught builder rejections.
